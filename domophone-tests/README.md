# Руководство по запуску автотестов домофона

Проект построен на базе `pytest` и использует универсальный фасад `run_method_test` для выполнения тестов.

## 1. Базовый запуск

Для запуска всех тестов из текущей директории (`domophone-tests`):

```bash
pytest
```

Результаты Allure будут сохранены в папку `allure-results`.

## 2. Фильтрация и выбор сценария

Используются CLI-флаги для управления типом теста и способом проверки.

### Выбор типа сценария (Positive/Negative)
По умолчанию все тесты запускаются как `positive`. Чтобы сменить тип:

```bash
pytest --type=negative
pytest --type=boundary
```

---

## 3. Выбор способа проверки (Control Backend)

Универсальный исполнитель `run_method_test` поддерживает три режима проверки результата:
1. **API** (по умолчанию) — проверка через контрольный метод API.
2. **WEB** — проверка через веб-интерфейс (Playwright).
3. **CONFIG** — проверка через файл конфигурации на устройстве.

Для выбора используется флаг `--control`:

```bash
pytest --control=web
pytest --control=config
```

Можно комбинировать флаги:
```bash
pytest --type=negative --control=web
```

---

## 4. Конфигурация окружения

Параметры подключения к устройству и путь к БД задаются в файле `config/test_config.yaml`.
Можно переопределить путь к конфигу через переменную окружения:

```bash
$env:TEST_CONFIG="config/my_custom_config.yaml"  # PowerShell
set TEST_CONFIG=config/my_custom_config.yaml     # CMD
```

---

## 5. Полезные флаги pytest

- `-v` — подробный вывод.
- `-s` — отображение `print` и логов в реальном времени.
- `--alluredir=allure-results` — путь для отчетов (уже настроен в `pytest.ini`).
- `--lf` (last failed) — запустить только тесты, которые упали в прошлый раз.

## 6. Генерация отчета Allure

После завершения тестов:

```bash
allure serve allure-results
```

---

## 7. Графический интерфейс (GUI Launcher)

Для удобного запуска тестов и использования утилит предусмотрена графическая оболочка на базе `PyQt6`.

### Запуск GUI:
```bash
python tools/gui_launcher.py
```

### Возможности:
- **Test Execution**: Выбор типов тестов (Positive/Negative/Boundary) и способов проверки (API/Web/Config) через чекбоксы.
- **Config Sync**: Удобный интерфейс для синхронизации параметров из файлов конфигурации (.dat/.json).
- **API Sync**: Интерактивное добавление новых API-методов и привязка их параметров к базе данных.
- **Логирование**: Просмотр вывода тестов и работы утилит в реальном времени прямо в окне приложения.

---

## 8. Утилиты синхронизации БД

В папке `tools/` находятся скрипты для наполнения и поддержки актуальности базы данных параметров.

### 8.1. Синхронизация конфигурации (`config_sync.py`)
Используется для добавления новых параметров из расшифрованного файла конфигурации устройства.
```bash
python tools/config_sync.py <путь_к_файлу_конфига> [-fw <версия_прошивки>]
```
- Поддерживает рекурсивный обход вложенных объектов и массивов.
- Предлагает автоматическое копирование параметров из предыдущих версий прошивок.

### 8.2. Синхронизация API-методов (`api_sync.py`)
Позволяет добавлять API-методы и связывать их параметры с параметрами конфигурации (`config_parameters`).
```bash
python tools/api_sync.py <версия_прошивки>
```
**Ключевые функции:**
- Интеллектуальный поиск параметров по части имени или пути.
- **Маппинг через JSON**: Вставьте JSON-образец ответа/запроса API, и утилита сама предложит подходящие `param_uuid` из базы данных.
- Копирование всех методов и параметров из одной прошивки в другую.
